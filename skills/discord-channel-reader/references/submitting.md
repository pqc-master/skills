# 현재 문제 채널에 소스코드와 보고서 제출하기

제출 대상은 **현재 풀고 있는 문제의 채널**이다. 설정 화면에서 채널을 고정하지 않는다. 봇 토큰과 표시 이름만 설정하면, 제출 명령이 해당 채널의 자기 웹훅을 재사용하거나 생성해 `이름 · Codex`로 두 파일을 보낸다. 웹훅 URL을 직접 입력하거나 공유할 필요가 없다.

## 준비할 파일과 대상

- 문제를 푼 소스코드 ZIP 한 개.
- UTF-8 Markdown 보고서 한 개.
- 사용자가 지정한 문제 채널 이름·Discord 채널 링크·ID 또는 문제를 읽을 때 확인한 채널.

기본 서버는 `1563153526283051008`, 기본 카테고리는 `1570317863984701441`이다. 사용자는 **채널 이름만 지정해도 된다.** 이름을 받으면 에이전트가 `read channels`로 기본 카테고리의 실제 목록을 조회하고, 이름이 정확히 일치하는 채널이 하나일 때 그 ID를 사용한다. 다른 범위를 명시했다면 해당 카테고리의 목록을 `read channels --category-id CATEGORY_ID`로 조회하고 반환된 서버·카테고리를 확인한다. 부분 일치나 첫 번째 검색 결과를 임의로 선택하지 않는다. 이름이 없거나 중복되거나 목록을 읽을 수 없을 때만 대상 링크·ID 등 필요한 정보를 확인한다. 이름이 유일하게 확인되면 사용자에게 ID를 직접 복사해 달라고 요구하지 않는다.

작업 대상 채널을 이미 읽었다면 그때 확인한 ID를 계속 사용한다. 조회·첨부 다운로드·미리보기·제출에는 같은 ID를 전달하고, 채널 이름과 확인된 링크·ID를 작업 근거에 남긴다. 카테고리 ID를 채널 ID로 사용하거나 이전 작업의 채널로 보내지 않는다. 제출 전에 실제 소속을 검사한다.

소스 ZIP은 해당 풀이에 필요한 코드·실행 안내·의존성 목록을 포함한다. 봇 토큰, `.env` 비밀 값, 비밀키, `.git`, 가상환경, 캐시, 내려받은 전체 대화 기록은 넣지 않는다. 보고서에는 풀이 접근, 실행·재현 방법, 확인한 결과와 남은 한계를 정리한다. 제출 전 ZIP 목록과 보고서 내용을 확인한다. 스크립트는 주어진 파일을 그대로 보내며 내부 내용을 임의로 삭제하거나 변환하지 않는다.

## 미리보기

실행 파일로 설치했다면 다음을 사용한다. Windows는 `pqc-discord.exe`이며 `<SKILL>`은 실제 설치 경로다.

```sh
<SKILL>/bin/pqc-discord submit preview --channel-id CHANNEL_ID --source-zip ./solution.zip --report ./report.md
```

여기서 `CHANNEL_ID`는 이름 조회 또는 제공된 링크·ID에서 에이전트가 확정한 값이다. CLI의 `--channel-id`에는 이름 대신 이 ID를 전달한다.

소스 설치에서는 `python3 <SKILL>/scripts/discord_submit.py preview ...`를 사용한다. 미리보기는 네트워크·봇 토큰 조회 없이 표시 이름, 대상 ID, 실제 첨부 파일 이름, 두 파일의 크기·해시와 메시지 내용을 보여준다. 채널 권한 확인이나 웹훅 생성은 하지 않는다.

## 제출

사용자가 결과 제출까지 요청한 경우, 대상과 두 파일을 확인하고 실행한다. 단순 조회·분석·초안 작성 요청에는 실행하지 않는다.

```sh
<SKILL>/bin/pqc-discord submit send --channel-id CHANNEL_ID --source-zip ./solution.zip --report ./report.md
```

표시 이름은 게시물 상단의 `이름 · Codex`와 첨부 파일 이름에 반영된다. 표시 이름이 `민영`이면 두 파일은 한 메시지에 **`sourcecode_민영.zip`과 `report_민영.md`**로 첨부된다. 미리보기와 실제 제출은 같은 이름을 사용하며 로컬 원본 파일의 경로·이름·바이트·해시는 바꾸지 않는다.

첨부 파일 이름에서는 한글을 유지하고, 공백과 경로 구분자 및 `<>:"/\\|?*`를 `_`로 바꾼다. 이름 앞뒤의 점·밑줄을 제거한 뒤 빈 이름이 되면 `user`를 쓴다. 이 처리는 첨부 이름에만 적용하며 게시물 상단의 표시 이름은 바꾸지 않는다. 제어 문자나 보이지 않는 형식 문자가 포함된 표시 이름은 기존 규칙대로 거부한다.

일반 텍스트 채널과 이미 존재하는 스레드를 지원한다. 포럼·미디어는 기존 게시글의 스레드 ID를 사용하며 부모 채널에는 직접 제출하지 않는다. 새 채널·스레드를 만들지 않는다.

명령은 먼저 봇·서버·카테고리·대상 채널과 권한을 확인한다. 봇이 해당 채널에서 만든 `PQC Results` 웹훅만 재사용하고, 없으면 만든다. 다른 사람이나 다른 봇의 웹훅을 변경·삭제하지 않는다. 웹훅의 토큰은 파일·로그·결과에 저장하지 않는다. `allowed_mentions`를 비활성화해 자동 멘션 알림을 보내지 않는다.

## 권한·한도·실패 처리

- 조회에는 **채널 보기·메시지 기록 읽기**, 작성자 이름을 붙인 제출에는 대상 채널의 **웹훅 관리** 권한이 필요하다. 스레드는 부모 채널의 웹훅을 사용하며 대상 스레드도 봇이 볼 수 있어야 한다.
- 파일당 20 MiB, multipart 전체 요청은 25 MiB 이내로 제한한다. 실제 서버가 더 큰 파일을 허용하더라도 이 버전은 보수적으로 제한한다. 초과하면 전송 전에 중단하고 파일을 줄이도록 안내한다.
- 잘못된 ZIP, 비어 있거나 UTF-8이 아닌 보고서, 잘못된 대상은 전송하지 않는다. 두 파일을 자동으로 분할하거나 잘라 보내지 않는다.
- 429는 응답의 대기 시간을 지키며 제한된 횟수로 재시도한다. 웹훅 생성이나 파일 전송 중 타임아웃·5xx·불완전한 응답은 결과 불명으로 처리하고 자동 재전송하지 않는다.
- 성공 응답의 채널·웹훅·첨부 두 개가 요청과 맞는지 확인한 뒤 메시지 링크를 반환한다. 결과가 불명확하면 대상 채널에서 실제 게시 여부를 먼저 확인한다.
- 표시 이름은 사용자가 정한 이름이다. 실제 Discord 사용자 계정 인증을 의미하지 않는다.

## 공식 근거와 검증

확인일: 2026-11-15. 실제 제출은 **NOT TESTED**이며 테스트에는 가상 파일·응답만 사용한다.

- [Uploading Files](https://docs.discord.com/developers/reference#uploading-files): multipart `payload_json`, `files[n]`, 첨부 파일 기본 한도.
- [RFC 7578 §4.2](https://www.rfc-editor.org/rfc/rfc7578.html#section-4.2): multipart 파일 이름과 비ASCII 이름의 UTF-8 처리.
- [Webhook API](https://docs.discord.com/developers/resources/webhook): 채널별 조회·생성, 작성자 이름 지정, `wait=true`, 스레드 ID.
- [Message API](https://docs.discord.com/developers/resources/message#create-message): 첨부 메타데이터와 전체 요청 크기.
- [Permissions](https://docs.discord.com/developers/topics/permissions): 채널·웹훅 관리 권한.
- [Rate Limits](https://docs.discord.com/developers/topics/rate-limits): 429 대기와 재시도.
