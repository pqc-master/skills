# PQC 전환

대상의 실제 암호 기능을 바꾸고 실행 가능한 변경을 남긴다. 알고리즘·매개변수·키 형식·호환 정책의 기술적 선택은 에이전트가 근거를 확인해 결정한다. 후보 목록만 제시하거나 사용자에게 보안 등급을 정하게 하지 않는다.

## 입력과 결정

- [pqc-identify](../pqc-identify/SKILL.md)의 대상 경로·커밋·사용처·선정 근거를 읽는다. 기록이 없거나 코드가 달라졌다면 필요한 식별을 먼저 수행한다. Toolkit과 대상의 작업 지침·미커밋 변경을 확인한다. 변경과 검증 산출물은 지정된 대상·문제 경로에만 남기고, 별도 수정 요청 없는 Toolkit은 읽기 전용 참고 자료로 사용한다.
- [선정 기준](../pqc-identify/references/selection-policy.md)과 공식 명세·API를 대조해 정확한 알고리즘·매개변수·라이브러리 버전, 서명 모드·컨텍스트 또는 KDF·AEAD를 확정한다. 기존 강도 보존, 상대 프로파일, 실제 크기·성능 조건과 대안을 비교한 이유를 남긴다.
- 출처로 해결할 수 있는 기술적 선택은 스스로 결정한다. 찾지 못한 외부 조건은 적용 범위와 가정으로 기록하되 확인된 필수 요구를 무시하지 않는다. 실제 호환 조건이 충돌하거나 필요한 구현이 없으면 영향받는 경로와 근거를 명시한다.

## 적용

1. 실제 키 생성·서명/검증·키 설정 진입점에 유지보수되는 구현체를 연결한다. 기존 코드의 호출 이름만 바꾸거나 앱과 무관한 별도 데모를 전환 완료로 제시하지 않는다.
2. 새 키·서명/암호문 형식을 식별하고, 키 보호·배포·복구·비밀번호 변경 등 연동 경로를 함께 바꾼다. 전환 대상인 기존 공개키 알고리즘의 함수·분기·우회 옵션을 제거하고 신규 키 생성·서명/키 설정·검증을 PQC 경로로 연결한다. 요청이나 확인된 필수 요구 없이 호환 모드를 추가하지 않는다. 과거 자료 검증을 유지해야 하는 명시 요구가 있다면 그 범위를 별도로 기록하며, 실패 후 자동으로 기존 알고리즘을 시도하지 않는다.
   새 PQC 키를 처리하기 위한 필수 연동과 별도의 보안 개선을 구분한다. 기존 대칭 암호·해시·비밀번호 KDF는 새 키 표현을 안전하게 처리할 수 있으면 유지한다. 변경이 필요하면 실제 형식·API의 제약과 선택 이유를 기록하고 PQC 공개키 알고리즘 전환 실적으로 혼합하지 않는다.
3. 실패 시 인증되지 않은 내용·비밀이 출력되지 않도록 한다. 난수 경로와 필수 강도 조건, 파일 권한·잘림·크기 제한을 확인한다. 외부 원시 암호 코드를 새로 구현하거나 전체 업스트림을 불필요하게 복제하지 않는다.
4. 재현할 수 있는 패치/커밋과 빌드 명령을 남긴다. 구현 중 필요한 컴파일 확인은 직접 수행하고, 최종 기능·회귀·비정상 입력 시험은 아래 별도 에이전트에 맡긴다.

## 독립 검증 인계

전환 코드가 준비되면 [검증 에이전트 지침](references/verification-agent.md)을 읽고 별도 에이전트에 테스트를 위임한다. 가능한 경우 이전 대화 없이 대상·고정 커밋/패치 해시·동작 명세·빌드/시험 명령·원본 기준·허용 출력 경로만 넘긴다. 자신의 예상 결론이나 성공 판정을 전달하지 않는다.

검증 중에는 해당 소스 스냅샷을 변경하지 않는다. 메인 에이전트는 근거 정리·양식 확보 여부 확인 등 독립 작업을 병행한다. 검증자는 별도 빌드/임시 디렉터리에서 실행하고 소스를 수정하지 않는다. 실패가 오면 메인 에이전트가 수정한 새 스냅샷을 넘겨 관련 시험을 재실행한다. 시간 절약을 위해 무관한 언어·OS·벤치마크는 기본 필수 시험에 포함하지 않는다.

에이전트 도구가 없으면 독립 검증을 수행한 것처럼 말하지 않는다. 같은 검증을 로컬로 수행할 수 있으면 실행하고 독립 검증은 `NOT TESTED`로 기록한다. 빠른 제출이 필요해도 필수 시험 실패·미실행을 성공으로 바꾸지 않는다.

## 결과와 다음 단계

적용 범위·선정 근거·변경 커밋/해시, 원본과 달라진 형식·호환 동작, 검증자가 실행한 환경·명령·결과·남은 제한을 같은 사례 기록에 모은다. `전환 구현`, `독립 검증`, `보고서` 상태를 분리한다. 검증은 실행한 스냅샷에만 연결하고 수정 후 오래된 성공 기록을 재사용하지 않는다.

`보고서 작성` 요청은 [pqc-report](../pqc-report/SKILL.md)로 넘긴다. 사용자가 승인한 워크플로가 실제 동봉 양식을 선택했다면 그 경로도 함께 전달한다. 제공되거나 선택된 양식이 없으면 근거 기록을 유지하고 보고서는 `양식 대기`로 둔다. 양식 부재로 전환·검증을 멈추거나 임의의 제출 양식을 만들지 않는다.
