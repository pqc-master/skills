# PQC 전환 대상 식별

사용자가 지정한 프로젝트를 분석해 **무엇을 왜 전환하고 어떤 알고리즘·매개변수를 사용할지** 설명한다. 호출 목록은 분석의 재료이며 최종 판정은 소스·설정·키 흐름·실행 근거를 종합한다. 알고리즘 일반 설명만 요청한 경우에는 저장소 분석을 시작하지 않는다.

알고리즘·매개변수는 에이전트가 공식 자료와 대상 요구를 대조해 선정한다. 사용자에게 후보 중 하나를 고르게 하거나 보안 카테고리를 대신 정하게 하지 않는다. 문서·코드에서 찾을 수 있는 요구는 먼저 조사하며, 명시되지 않은 외부 조건은 확인된 사실과 구분해 적용 범위·설계 가정·재선정 조건으로 남긴다. 실제 필수 요구의 충돌이나 지원 구현의 부재가 있을 때만 해당 경로를 보류한다.

## 대상과 범위

- 대상 경로·커밋·미커밋 변경, 언어·프레임워크·의존성·빌드 진입점을 확인한다. Toolkit과 분석 대상 저장소를 구별하고 각각 적용되는 `AGENTS.md`를 따른다. 여러 문제를 함께 관리하면 지정된 문제의 소스와 근거 경로를 구분하고 다른 문제의 결과를 섞지 않는다.
- 대상의 소스·설정·키 저장·통신 경계 중 조사한 범위와 제외한 부분을 기록한다. 라이브러리 포함이나 문자열 등장만으로 실제 사용을 확정하지 않는다.
- 식별 요청만으로 대상 암호 코드를 교체하지 않는다. 빌드·실행은 대화에서 허용된 범위 안에서 진행하고, 실행하지 않은 항목은 `NOT TESTED`로 남긴다.

## 암호 역할과 흐름 확인

파일·심볼 위치부터 찾아 필요한 호출부와 호출자를 읽는다. `rg --files`, `rg -l`, API 이름만 출력하는 `rg -n -o` 등을 활용하고 비밀키·공유 비밀·비밀번호·원문 인수를 결과에 복사하지 않는다.

암호 사용처마다 다음을 연결한다.

- **역할:** 서명, 키 설정, 키 보호, 데이터 암호화, MAC, 해시, KDF, 난수 중 실제 용도.
- **흐름:** 앱 진입점 → 래퍼·라이브러리 호출 → 저장/전송 형식 → 검증·복호화·실패 처리. 같은 API가 서로 다른 데이터를 인증하는 경우 구별한다.
- **키:** 생성·입력·파생·저장·배포·신뢰의 출처, 키 수명과 교체 조건. key-id와 인증된 공개키를 구별한다.
- **상대·제약:** 검증기·프로토콜·인증서·기존 데이터의 호환성, 표준 요구, 크기·성능 제약. 알 수 없는 상대 지원은 가정하지 않는다.

정적 호출, 실제 링크, 실행 확인을 구분한다. 래퍼·함수 포인터·동적 선택·조건부 빌드는 호출자와 빌드 설정을 추가로 확인하고, 근거가 부족하면 추가 조사 대상으로 둔다. 검색 결과가 없거나 읽지 못한 파일이 있다는 이유로 전환 불필요를 결론 내리지 않는다. 조사한 범위·제외한 경로·확인하지 못한 의존성을 함께 기록한다.

## 전환·유지·추가 조사 판정

스킬 설치 경로의 상위 폴더를 Toolkit으로 단정하지 않는다. 사용자가 지정한 Toolkit 경로가 있으면 그 안의 `docs/MIGRATION.md`, `docs/ALGORITHMS.md`, `docs/LANGUAGE_SUPPORT.md` 중 존재하는 자료만 읽기 전용으로 참고한다. 스킬만 설치했거나 자료가 없으면 함께 설치된 [선정 기준](references/selection-policy.md)과 대상 소스·공식 명세·API 자료로 확인한다. 새로운 버전·API·매개변수의 지원은 공식 자료로 확인한다. 분석·선정 근거는 대상 프로젝트의 지정된 기록 경로에 남기며 별도 수정 요청 없이 Toolkit에 쓰지 않는다.

실제 전환 판정에는 [기존 기능별 전환 기준](references/selection-policy.md)을 적용한다. 기존 기능·알고리즘/모드·키 크기/곡선·해시를 확인하고 전환 이유와 보존할 기능·강도를 먼저 정한다. 같은 RSA라도 서명과 키 보호를 구별한다. 이 근거로 후보·키/형식의 연동 변경·시험을 제시하며, 매개변수 기본값을 먼저 정해 전환 이유로 쓰지 않는다.

- 보안 강도 비교에는 [NIST 보안 카테고리 1–5](https://csrc.nist.gov/Projects/Post-Quantum-Cryptography/Post-Quantum-Cryptography-Standardization/Evaluation-Criteria/Security-%28Evaluation-Criteria%29)를 사용한다. **후보 매개변수의 카테고리**는 공식 명세로, **대상의 요구 최소 카테고리**는 적용되는 정책·고객/대회 요구사항 등으로 각각 확인한다. KpqC 명세의 강도 주장과 NIST FIPS 표준화·인증 여부를 구분한다.
- 기존 고전 강도는 SP 800-57 Rev. 5 표 2, EdDSA는 RFC 8032 §8.5 등으로 확인한다. NIST 후보는 IR 8547 최종본 표 3(서명)·5(KEM)의 고전 강도와 카테고리를 각각 대조한다. 상세 표·링크는 위 전환 기준에 있다. 기존 강도를 임의의 PQC 카테고리로 환산하지 않는다. 명시된 최소 카테고리가 없으면 해당 요구는 `미확인`으로 유지한다.
- 동일 기능·보존할 고전 강도와 확인된 최소 카테고리를 모두 충족하는 후보를 남기고, 정확한 프로파일·상대 지원·표준 요구·크기·실측 성능으로 선택한다. 사용할 정확한 집합·공식 카테고리와 선택·제외 이유, 적용한 공식 표의 버전·번호를 기록한다. 높은 카테고리라도 상대의 지정 프로파일을 대체할 수 있다고 가정하지 않는다. 별도 역할의 AES 키 길이·루트 키·보호 기간만으로 자동 등급을 부여하지 않으며, 등급 확인이 안 된 동안에도 역할·키 흐름·호환성 분석은 계속한다.
- RSA-PSS·ECDSA·Ed25519 등의 서명은 상대 지원·형식·키 배포를 포함해 PQC 서명 후보를 선정한다. 특정 알고리즘을 항상 최선으로 고정하지 않는다.
- RSA-OAEP 키 보호와 DH/ECDH/X25519 키 설정은 실제 역할에 맞는 KEM·KDF·AEAD·상대 인증/키 확인 설계를 검토한다. 알고리즘 이름만 바꾸거나 임의 하이브리드를 구성하지 않는다.
- AES·HMAC·해시·KDF·난수는 공개키 암호와 역할을 구분한다. 자동 교체 대상으로 삼지 말고 키 출처·길이·인증 범위·프로토콜 의존성을 검토해 유지 또는 별도 개선 근거를 남긴다.
- 미확인 라이브러리·빌드 분기·외부 시스템은 추가 조사로 남긴다. 정적 발견을 `VERIFIED`나 PQC 적용 완료로 승격하지 않는다.

## 결과와 다음 작업

기존 사례 문서나 요청한 답변 한 곳에 대상 커밋·범위·근거 위치와 다음 항목을 간결하게 정리한다. 별도 보고서 생성기나 필수 JSON 양식은 만들지 않는다.

분석 기록에는 대상 분석·선정 이유·정량값·검증 근거를 남긴다. 보고서 본문은 실제 양식을 받은 뒤 `pqc-report` 단계에서 작성한다. 판단을 뒷받침하지 않는 기초 용어 설명이나 대화 중의 오해 해명은 근거 기록에 넣지 않는다.

| 사용처·위치 | 역할·키/데이터 흐름 | 소스·실행 근거 | 전환/유지/연동 변경/추가 조사 | 이유·호환성·다음 검증 |
| --- | --- | --- | --- | --- |

전환안에는 기존 기능·키/해시와 강도 근거, 양자 취약성, 보존할 고전 강도·명시된 최소 PQC 카테고리, 공식 표로 좁힌 후보와 제외 이유, **선정 알고리즘·정확한 매개변수·공식 카테고리**, 키/서명·암호문 크기, 선택 이유·재선정 조건과 함께 바꿀 경로를 남긴다. 후보 나열만으로 선정 완료라고 하지 않는다. 근거 부족·필수 조건 충돌은 선정 보류로, 구현용 선택의 미확인 운영 조건과 앱 시험은 별도 상태로 기록한다. 같은 조건은 표 아래에 한 번만 정리해도 된다.

보고서에 사용할 문서 버전·상태·확인일·절/표·쪽수와 짧은 원문 발췌·번역을 대상의 근거 기록에 보존한다. 지정된 Toolkit의 `docs/SELECTION_EVIDENCE.md`가 있으면 참고할 수 있지만, 없으면 공식 원문을 직접 확인하며 없는 문서를 인용하지 않는다. 공식 사실, 프로젝트의 선택·가정, 실제 측정 결과를 구분한다. 매개변수 이름과 키 비트/바이트 크기·표현을 구별하고 실험용 선정·운영용 선정·실제 적용 검증을 각각 표시한다. 최솟값을 운영용 기본값으로 자동 확정하지 않는다.

같은 업무 기능의 여러 호출은 묶되 서명 대상·키·신뢰 경계가 다르면 구분한다. 실제 실행한 명령·환경·결과, 재사용한 검증 기록, 미확인 항목을 분리한다. 마지막에는 우선 적용할 한 경로와 정상·변조·잘못된 키·기존 형식·다운그레이드 시험을 제시한다. 식별과 실제 PQC 적용·전환 검증의 완료 여부를 따로 보고한다.

## 다음 단계로 인계

`pqc 전환` 요청은 [pqc-migrate](../pqc-migrate/SKILL.md)로 이어진다. 대상 경로·커밋, 사용처·선정 이유·정확한 매개변수, 호환 정책, 변경할 키/형식/호출 경로와 필수 시험을 같은 사례 기록에 남겨 넘긴다. 사용자가 식별부터 전환까지 요청했다면 재승인이나 매개변수 선택 질문 없이 이어서 적용한다. 식별만 요청한 경우에는 이 결과까지 완료한다. `보고서 작성`은 [pqc-report](../pqc-report/SKILL.md)에서 제공된 실제 양식을 기준으로 수행한다.
