# PQC 보고서 작성

사용자가 제공한 실제 양식과 제출 지침을 기준으로 작성한다. HWPX를 포함해 파일을 먼저 읽고 항목·분량·표·참고문헌·첨부 규칙을 확인한다. 사용자가 승인한 워크플로가 동봉 양식을 명시적으로 선택해 전달한 경우에도 그 파일을 입력 양식으로 사용한다. 예를 들어 `pqc-discord-workflow`의 Markdown 보고서 요청은 동봉 `assets/report-template.md`를 사용할 수 있다. 채널의 공식 제출 양식이 있으면 이를 우선하며 내부 기본 양식을 공식 양식으로 설명하지 않는다. 어느 양식도 제공·선택되지 않았다면 임의의 목차·HWPX·제출본을 만들지 않고 `양식 대기`를 기록한다. 필요한 근거는 기존 사례 문서에 유지한다.

스킬 설치 경로의 상위 폴더를 Toolkit으로 단정하지 않는다. 사용자가 지정한 Toolkit 경로에 근거 문서가 있으면 읽기 전용으로 참고하고, 없으면 대상의 기존 기록과 공식 출처에서 근거를 확인한다. 없는 문서나 원문을 읽은 것처럼 인용하지 않는다. 보고서와 추가 근거는 지정된 대상·문제의 출력 경로에만 남긴다.

## 입력과 작성

- [pqc-identify](../pqc-identify/SKILL.md)의 조사 범위·전환 판단·공식 출처와 [pqc-migrate](../pqc-migrate/SKILL.md)의 실제 변경·호환 정책·검증 에이전트 결과를 읽는다. 대상 커밋과 시험한 스냅샷이 일치하는지 확인한다.
- 실제 양식의 각 항목에 기존 구조·키/데이터 흐름, 전환 대상과 이유, 정확한 알고리즘·매개변수·실제 크기·선정 근거, 적용 변경, 문제→수정→재시험 증거를 연결한다. 이 분류를 공식 양식의 제목으로 가정하지 않는다.
- 대상의 원문 근거 기록에서 문서명·버전·상태·절/표·쪽수·공식 URL·확인일과 필요한 짧은 발췌·번역을 양식이 허용하는 위치에 적는다. 지정된 Toolkit의 `docs/SELECTION_EVIDENCE.md`는 존재할 때만 참고한다. 프로젝트의 결정·가정, 공식 사실과 실측 결과를 구분한다.
- 알고리즘 선택을 사용자에게 다시 요구하지 않는다. 전환 중 이미 에이전트가 내린 결정과 근거를 설명한다. 근거와 충돌하는 문서 내용은 원자료로 해결하며 미실행 시험을 완료로 쓰지 않는다.
- 내부 경로나 PR 링크만으로 증명을 대신하지 않고 코드 위치·변경 커밋·명령·환경·결과를 남긴다. 비밀 자료와 기초 용어 설명·대화 중의 오해 해명은 보고서에 옮기지 않는다.

## 파일 검증과 결과

원본 양식을 보존하고 사본에 작성한다. 지원되는 편집 경로를 실제 파일에서 검증하고, 최종 파일을 다시 열어 표·글꼴·쪽 나눔·참조·누락을 확인한다. HWPX 지원을 확인하지 않은 도구의 자동 변환을 약속하지 않는다. 중간 형식을 썼다면 최종 HWPX에서 다시 확인한다.

내용 작성과 파일 열기·서식 검증의 상태를 구분해 반환한다. 원래 제출 요구와 다른 형식으로 임의 대체하거나 제출하지 않는다. 양식 부재는 보고서 단계의 대기 사유이며 이미 허용된 전환·독립 검증을 막지 않는다.
