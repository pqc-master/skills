# 전환 전후의 실제 요청 성능 측정

목적은 변경한 암호 경로가 **해당 서비스의 실제 요청 시간과 자원·전송량에 미치는 영향**을 측정하는 것이다. “ECDSA보다 ML-DSA 서명은 크지만 성능 차이는 작다”는 가설로만 취급한다. 예상에 맞춰 측정값을 선택하거나 결론을 먼저 쓰지 않는다.

## 측정 대상과 기준 상태

1. 원본의 소스 해시·빌드·정상 동작을 보존한다. 수정본과 원본은 별도 폴더와 별도 결과 파일을 사용한다. 원본이 실행되지 않는다면 수정한 기준선이 무엇인지 기록하고 원본 성공으로 쓰지 않는다.
2. 대상의 실제 서명·검증 또는 키 설정을 수행하는 요청 경로를 찾는다. 암호 함수를 전혀 부르지 않는 건강 확인 API나 단순 응답만 비교하지 않는다. 서명·검증 호출이 실제 수행되는지 증거를 남긴다.
3. 서비스에 HTTP 요청이 있으면 클라이언트 요청 시작부터 응답 완료까지 측정한다. CLI·파일 처리 프로젝트라면 실제 기능 작업 시간을 측정하고 HTTP 요청 시간과 구분한다. 없는 서비스 계층을 만들어 실제 서비스 성능인 것처럼 제시하지 않는다.
4. 프로젝트의 허용 한도·대표 입력 크기·동시 요청 수를 확인한다. 요구 한도가 없다면 측정 조건과 관측 결과만 보고하고 임의 합격선을 만들지 않는다.

## 같은 조건을 고정

OS·CPU·메모리, 언어·컴파일러·최적화 옵션, 라이브러리 버전, 서버/클라이언트 위치, 데이터베이스 상태와 입력 데이터를 기록한다. 기존 ECDSA는 곡선·해시·서명 인코딩을, ML-DSA는 정확한 매개변수·서명 모드·컨텍스트를 기록한다. 키 생성·로딩이 매 요청에 포함되는지도 구분한다.

요청 본문 크기, 서명 개수, 연결 재사용·TLS·캐시 조건, 동시성, 시간 제한, 워밍업 횟수와 측정 반복 수를 전후 동일하게 적용한다. 로컬 루프백 측정은 실제 WAN·모바일망 성능의 근거로 확대하지 않는다. 네트워크 제한을 모사하면 설정값과 모사라는 사실을 표시한다.

가벼운 예비 실행으로 측정 가능한 반복 수와 범위를 정한 뒤 본 측정 조건을 고정한다. 워밍업은 집계에서 제외하고 독립된 여러 회차를 측정한다. 전후 순서에 따른 편향이 우려되면 실행 순서를 번갈아 수행한다. 부하 생성기와 다른 작업의 경합을 확인한다. 운영 서비스에 임의의 부하를 발생시키지 말고 허용된 시험 환경을 사용한다.

## 반드시 구분할 수치

| 구분 | 기록할 값 |
| --- | --- |
| 암호 결과 크기 | 원시 서명/암호문 바이트, 실제 인코딩 후 크기, 요청·응답 전체 전송 크기 |
| 암호 연산 | 해당 경로의 키 생성·서명·검증 또는 캡슐화·디캡슐화 시간. 측정하지 않은 것은 별도 표시 |
| 전체 요청 | 성공 요청의 평균·p50·p95, 총 시도 수·성공 수·실패 수·타임아웃 수 |
| 처리량·자원 | 요청/초와 측정 구간, 필요 시 메모리·CPU. 측정 도구와 집계 기준 |
| 재현 정보 | 회차·반복 수·워밍업·입력 크기·동시성·환경·명령·소스 및 실행물 해시 |

ECDSA의 DER 길이 변동이나 Base64·JSON·헤더 비용을 누락하지 않는다. 암호 함수의 소요 시간과 네트워크를 포함한 요청 시간을 같은 열에 섞지 않는다. 요청 크기를 바꿀 때는 대표 크기와 실제 한도 근처를 포함하되, 거부된 요청은 정상 성능 표본으로 넣지 않는다.

실패를 버리고 성공 요청만 빠르다고 설명하지 않는다. 성공 요청 지연 분포와 함께 실패율·타임아웃을 보고한다. 실패 종류와 실패 지연도 별도 근거로 보존한다. 처리량은 동시 실행 시간을 중복 합산하지 않고 실제 측정 구간의 벽시계 시간을 사용한다.

## 원시 기록과 비교

대상에 맞는 측정 스크립트를 프로젝트에 남기고 소스 ZIP에 포함한다. 원시 결과는 CSV 또는 JSONL로 보존하며 다음 정보가 재구성 가능해야 한다.

```text
variant, round, request_index, payload_bytes, concurrency,
success, status_or_error, elapsed_ms, signature_bytes, wire_bytes
```

관측하지 않은 값은 0으로 채우지 말고 비워 두거나 `NOT TESTED`로 표시한다. 인증 토큰·키·실제 민감한 요청 본문은 원시 기록에 넣지 않는다. 명령은 재현 가능한 비밀 없는 형태로 기록한다.

전후 조건별로 평균의 절대 차이(ms), 상대 차이(%), p50·p95와 실패율을 비교한다. 원본 평균이 0이거나 비교 조건이 다르면 상대 차이를 계산하지 않는다. 회차별 변동·표본 수를 함께 보고하고 평균만으로 통계적 동등성을 주장하지 않는다. “차이가 작다”는 표현은 명시된 업무 허용치와 변동 폭을 함께 설명할 수 있을 때만 사용한다.

범주 1·2·5 또는 하이브리드를 예외로 선택했다면 실제 구현한 후보의 비교 근거를 기록한다. 모든 후보를 측정했다고 가정하지 않는다. 측정 불가·기준선 부재는 이유와 `NOT TESTED`를 남기고 성능 비교 완료로 표시하지 않는다.
