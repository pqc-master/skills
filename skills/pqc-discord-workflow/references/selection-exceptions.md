# 범주 3 기본 검토와 예외 근거

이 문서는 사용자가 승인한 Discord PQC 작업의 팀 방침이다. 공통 [기존 기능별 선정 기준](../../pqc-identify/references/selection-policy.md)에 **워크플로의 명시적 기본 검토 방침**으로 전달한다. 대상의 기존 기능·고전 강도·명시된 최소 PQC 범주·상대 프로파일을 먼저 조사하는 절차를 대체하지 않는다. 이 워크플로에서는 공통 기준의 “요구가 없는 로컬 실험에서 가장 작은 집합부터 시험”하는 순서보다 아래의 범주 3 우선 검토 순서를 적용한다. 필수 요구·기존 강도 보존과 예외 근거 기록은 그대로 적용한다.

## 기본 선택의 의미

- 일반적인 키 설정은 ML-KEM-768, 일반적인 전자서명은 ML-DSA-65를 범주 3 후보로 먼저 검토한다. 실제 역할에 맞는 알고리즘, 정확한 매개변수, 구현 버전과 운용 모드를 선정한다. 암호 사용이 없는 프로젝트에 이를 새로 추가하지 않는다.
- 이 기본값은 팀의 출발점이며 NIST가 모든 서비스에 범주 3을 의무화한 것이 아니다. NIST의 ML-KEM-768 기본 권고와 팀의 ML-DSA-65 우선 검토 방침을 구별한다.
- 문제·정책의 필수 최소 조건, 기존에 보존해야 할 더 높은 강도, 정확한 표준 프로파일이나 호환 요구가 있으면 이를 함께 충족한다. 범주 3을 적용하기 위해 기존의 더 높은 요구를 낮추지 않는다.
- 팀의 기본 검토값과 대상에 명시된 필수 최소 범주는 별도 항목으로 기록한다. 대상의 최소 범주가 명시되지 않았다면 그 사실을 기록하며, 팀 기본값을 외부 필수 요구로 바꾸어 쓰지 않는다.

| 역할 | 기본 검토 | 같은 계열의 다른 매개변수 |
| --- | --- | --- |
| 키 설정 | ML-KEM-768 · 범주 3 | ML-KEM-512 · 범주 1 / ML-KEM-1024 · 범주 5 |
| 전자서명 | ML-DSA-65 · 범주 3 | ML-DSA-44 · 범주 2 / ML-DSA-87 · 범주 5 |

매개변수 이름의 숫자는 키 비트 길이가 아니다. 실제 키·서명·암호문 바이트 크기와 전송 형식은 따로 확인한다. 명세의 범주 주장과 구현의 난수·검증 조건 충족을 구별한다. 특히 ML-DSA-44는 FIPS 204 §3.6.1의 RBG 조건을 포함해 검토하며 범주 1 매개변수라고 설명하지 않는다.

## 예외는 조건과 증거로 설명

| 확인한 조건 | 검토 방향 | 보고서에 남길 근거 |
| --- | --- | --- |
| 보존할 강도나 필수 요구가 더 높음 | 해당 요구를 충족하는 범주 5 등 후보 | 적용 정책·기존 강도·정확한 매개변수·비용 |
| 측정된 메모리·통신량·요청 시간이 허용치를 넘음 | 구현·형식 최적화 후 재측정, 다른 허용 후보 비교 | 허용치 출처, 실제 장치·수치, 후보 제외 이유 |
| 범주 1 또는 2 후보가 필요함 | 해당 알고리즘의 실제 매개변수와 모든 필수 요구를 대조 | 범주 3 기본안의 부적합 증거, 강도 보존, 호환 조건과 잔여 제한 |
| 기존 상대와 병행해야 하는 명시적 요구가 있음 | 지원되는 표준 프로토콜의 하이브리드·전환 방식 | 프로파일·결합 방식·상대 지원·실패 정책·추가 비용 |
| AES·해시·MAC·KDF에 별도 제약이나 약점이 있음 | 해당 역할에 맞는 유지 또는 별도 보강 | 실제 사용처·키 출처·모드·길이·인증 범위·변경 이유 |

필수 보안 요구나 기존 보존 강도를 어기는 하향 선택은 성능 최적화로 정당화하지 않는다. 먼저 구조·구현·프로토콜의 허용 가능한 변경을 검토하며 해결되지 않으면 충돌한 경로를 보류한다. 과거 자료 검증 등 명시적 호환 범위를 제외하고 PQC 실패 시 기존 암호로 조용히 우회하지 않는다.

하이브리드는 카테고리가 아니며 두 이름을 연결하는 것만으로 보안 성질을 보장하지 않는다. 암호 원시 기능·공식 프로토콜 프로파일·실제 라이브러리 지원을 구분한다. 알고리즘 선택, 구현 완료, 기능·보안 검증, 운영 배포 준비를 각각 표시한다.

예외 기록에는 **기본안 → 충족하지 못한 조건 → 확인한 근거 → 비교한 대안 → 최종 선택 → 검증 결과 → 재선정 조건**을 남긴다. 예외가 없으면 없다고 쓰되 검토하지 않은 항목을 충족으로 표시하지 않는다.

## 공식 근거

확인일: 2026-11-15. 새로운 구현·버전·프로토콜 지원을 채택할 때는 해당 공식 자료를 추가 확인한다.

- [FIPS 203 §4·§8](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.203.pdf): ML-KEM의 범주 1·3·5, ML-KEM-768 기본 권고와 다른 집합의 선택 조건.
- [FIPS 204 §3.6.1·§4·표 1–2](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.204.pdf): ML-DSA의 범주 2·3·5, RBG 조건, 키·서명 크기.
- [NIST 보안 범주 평가 기준](https://csrc.nist.gov/Projects/Post-Quantum-Cryptography/Post-Quantum-Cryptography-Standardization/Evaluation-Criteria/Security-%28Evaluation-Criteria%29): 범주의 비교 기준. 기존 알고리즘의 키 비트 수와 PQC 범주를 같은 숫자로 대응시키지 않는다.
