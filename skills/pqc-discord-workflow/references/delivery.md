# 두 산출물의 구성과 최종 검증

전환된 서비스가 들어 있는 **전체 프로젝트 ZIP**과 UTF-8 **Markdown 보고서**를 만든다. 배포 파일·근거·시험 임시 경로는 원본과 프로젝트 밖에 두어 ZIP 안으로 자기 자신이나 이전 산출물이 들어가지 않게 한다.

## 전체 프로젝트 구성

ZIP에는 전체 소스, 빌드 설정·의존성 고정 정보, 실행에 필요한 자산, 비밀 없는 설정 예시, 실행 안내와 테스트·벤치마크 재현 코드를 포함한다. 변경한 파일만 묶거나 원래 서비스 대신 별도 암호 데모를 제출하지 않는다. 플랫폼별로 필요한 외부 도구·라이브러리 설치 명령과 검증한 버전을 기록한다.

전후 원시 벤치마크와 비밀 없는 검증 근거는 프로젝트 안의 명확한 경로에 포함한다. 기존 보고서·불필요한 로그를 무조건 모으지 않는다. `.env` 실제 값, 개인키·토큰·인증 정보, `.git`, 가상환경·의존성 캐시, 전체 Discord 대화 기록은 제출하지 않는다. `.env.example`처럼 비밀이 없는 설정 예시는 검토 후 포함한다. 공개 테스트 벡터·의도적으로 제공된 테스트 키가 필요한 프로젝트에서는 그 용도와 공개 출처를 분명히 하고 실제 개인키와 구별한다.

`workspace pack`은 알려진 비밀 파일·캐시 제외와 위험 경로 검사를 돕지만 모든 비밀이나 누락을 찾아내는 보증은 아니다. 제외 목록과 실제 ZIP 목록을 검토하고, 제거한 파일 때문에 필요한 기능이 사라지지 않았는지 재빌드로 확인한다. 업로드 한도에 맞추기 위해 필수 소스·자산을 삭제하지 않는다.

## 패키징과 새 폴더 재검증

아래 `<DISCORD>`는 함께 설치된 `discord-channel-reader`의 절대 경로다. Windows 실행기는 `.exe`를 붙인다. 소스 설치는 `python3 <DISCORD>/scripts/pqc_workspace.py ...`를 사용한다.

```sh
<DISCORD>/bin/pqc-discord workspace pack --project /ABSOLUTE/case/working --output /ABSOLUTE/case/deliverables/소스코드.zip
<DISCORD>/bin/pqc-discord workspace extract --archive /ABSOLUTE/case/deliverables/소스코드.zip --output /ABSOLUTE/case/final-rebuild
```

`pack`은 ZIP 옆의 `.manifest.json` 파일에 파일 목록·크기·SHA-256·실행 비트와 제외 내역을 남긴다. `extract`는 새 출력 폴더 옆의 `.extraction.json`에 추출 근거를 남긴다. 명령 결과의 `archive_sha256`, `file_count`, `total_bytes`, `manifest_path`와 실제 결과 경로를 사용하며 직접 이름을 추정하지 않는다. 추출 완료는 빌드 성공을 뜻하지 않는다. Windows의 파일 모드는 POSIX 실행 비트와 다르므로 Unix용 스크립트 실행 방법·권한은 원본 manifest와 실제 대상 환경에서 확인한다. ZIP을 만드는 동안 소스 파일과 디렉터리를 수정하지 않는다.

1. 전환 코드와 필요한 근거를 확정하고 `pack`을 실행한다. 결과의 ZIP 해시와 목록을 확인한다.
2. 만든 ZIP 자체를 새 폴더에 추출한다. 기록한 방법대로 의존성을 준비하고 빌드·기본 서비스 기능·필수 보안 테스트를 재실행한다. 원래 작업 폴더의 절대 경로·가상환경·기존 빌드 파일을 몰래 참조하지 않게 한다.
3. 실행한 명령·환경·종료 코드와 결과를 기록한다. 실제 시험한 ZIP 해시와 재빌드 결과를 연결한다. 이 단계의 로그는 프로젝트 밖에 저장한다.
4. 최종 재빌드 결과와 ZIP 해시를 보고서에 반영한다. ZIP을 재검증 후 수정하지 않는다. 수정이 필요하면 다시 포장하고 새 ZIP으로 재검증한다.

최종 ZIP 재빌드의 로그·파일 목록은 보고서 본문 또는 부록에 포함할 수 있다. 별도 로컬 경로만 제시해 수신자가 증거를 확인할 수 없게 하지 않는다. ZIP과 보고서 서로의 해시를 내부에 넣으려다 계속 재포장하지 않도록, **ZIP 해시는 보고서에, 최종 두 파일의 해시는 제출 미리보기와 게시 기록에** 남긴다.

## 보고서 작성

공식 양식이 있으면 해당 지침을 따른다. 별도 양식이 없고 이 워크플로의 Markdown 보고서를 요청했다면 [기본 보고서 양식](../assets/report-template.md)을 `pqc-report`에 전달한다. 사용자 요청으로 선택한 내부 작업 양식이며 대회·기관의 공식 양식이라고 설명하지 않는다.

각 상태는 `PASS`, `FAIL`, `NOT TESTED`로 구분한다. 적용 대상이 아닌 시험은 이유를 적어 `해당 없음`으로 구분한다. 구현체 공식 벡터, 독립 구현 간 상호운용, 앱 기능·보안, 성능 비교, 최종 ZIP 재빌드는 각각 기록한다. 다른 OS에서 실행한 결과로 이번 OS의 성공을 추론하지 않는다.

보고서에는 공개할 수 있는 사용자 작업 지시 원문과 추가 요구를 남긴다. 비밀 값을 가렸다면 가린 사실을 표시한다. 실제 사용하지 않은 프롬프트를 원문으로 만들거나 내부 시스템 지침·개인적인 추론 과정을 기록하지 않는다. 공유용 재현 프롬프트는 실제 입력과 별도로 표시한다.

## 게시 준비와 성공 판정

완료 게시에는 필수 기능·보안 검증과 최종 ZIP 재빌드가 통과해야 한다. 원본 실행 불가, 성능 미측정 등 남은 제한을 숨기지 않고 구현·검증·벤치마크·패키징·게시 상태를 따로 표시한다. 요청된 성능 비교를 수행하지 못했다면 전체 요청이 완료됐다고 쓰지 않는다.

게시 본문에는 전환 요약, 선정·예외 이유, 검증 결과와 근거 위치, 실제 요청 성능 변화, 작업 프롬프트 요약을 넣는다. 본문 길이를 넘는 정보는 보고서의 해당 절로 연결한다. 미리보기와 실제 전송에 같은 메시지·파일·채널을 사용한다.

현재 업로더는 각 파일 20 MiB, multipart 전체 25 MiB를 제한하며 첨부명은 표시 이름을 붙인 `sourcecode_이름.zip`, `report_이름.md`다. 실제 첨부명은 `preview`에서 확인한다. 로컬 파일명을 `소스코드.zip`, `보고서.md`로 만들어도 내용은 바꾸지 않는다. 크기를 초과하면 캐시·불필요한 결과물을 검토하되 필수 프로젝트를 줄이거나 자동 분할·다른 외부 저장소 게시로 바꾸지 않는다. 충족할 수 없으면 두 파일을 로컬에 제공하고 제출 한도를 알린다.

웹훅 권한은 실제 대상 채널에서 확인한다. 연결 완료라는 사용자 설명만으로 게시 성공을 가정하지 않는다. 성공 응답의 채널 ID·첨부 두 개를 확인하고 메시지 링크를 반환한다. 결과 불명은 게시 여부를 먼저 확인하며 자동으로 중복 제출하지 않는다.
